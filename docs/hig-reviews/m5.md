# HIG review: M5 queue and lists

Result: **PASS** after five fixes made during the gate (below). The milestone stays open for the user's review of the running app and for CI on the pushed branch. The checks that need a person (Orca, keyboard walk-throughs) are logged in `pending-screenshots.md` for M9, as decided on 2026-11-08.

## Findings

1. **[PASS] Reordering as the HIG lays it out.** Boxed Lists: "Include drag handles at the beginning of the rows, to allow moving them", with a menu "with items for “move up”, “move down,” […] (menu items for move actions are required for accessibility purposes)". Only Next in Queue's rows have the handle; Move Up is unavailable on the first, Move Down on the last (seen in the dark row menu). A drag moved by hand headless reordered the queue and the store.
2. **[FIXED] Download progress had no text.** Progress Bars: "Progress bars should have a text label that describes how much of the task has been completed … “12.1 of 30 MB downloaded”". A downloading row now says "1.1 MB of 2.3 MB downloaded" where its subtitle was, and the bar's accessible description says the same. Activity mode only until the server gives the size ("Activity mode should be avoided wherever possible"). One bar per episode, which the page allows when "it might be necessary to pause or stop a subtask": each has Cancel Download.
3. **[FIXED] Deleting one download had neither confirmation nor undo.** Dialogs: "Destructive actions should always be accompanied by either a confirmation dialog or an offer to undo the action". Delete Download now asks first, as Delete All Downloads does (Cancel first, Delete destructive, no default: "this should not be done if its action is irreversible, destructive").
4. **[FIXED] Items that ask first had no ellipsis.** Writing Style: "Use an ellipsis (…) at the end of a label if further input or confirmation is required". Delete Download… and Download All Episodes….
5. **[FIXED] Preferences labels.** Spin Buttons: "Label the spin button using sentence capitalization": Delete after. Writing Style: "Text generally shouldn't end with a period": Only Delete Played Episodes' subtitle is one sentence. Switches: "Label switches with nouns using header capitalization" and "Give the label an access key": both switch rows have access keys, as does the spin row. Next to its header-capitalized neighbours the sentence-case spin row looks uneven; it follows the page as written.
6. **[FIXED] Selection mode overflowed the narrowest window.** With three window buttons, "No Episodes Selected" made the selection header 430px wide at 360px; the heading now ellipsizes, and the narrow header test measures selection mode too.
7. **[FIXED] An empty progress bar.** A partly played episode whose feed gives no length drew a bar that could only stay empty; it is now left out.
8. **[PASS] Download All Episodes asks first.** Dialogs: "Label the affirmative button with a specific imperative verb" (Download), "Assign the return key to activate the affirmative button" (it is not destructive), Cancel first. Progress Bars: "If an operation is potentially destructive or resource-intensive, consider adding pause and/or cancel buttons", which each row's Cancel Download is.
9. **[PASS] Toasts.** Toasts: "Each toast should have a short and simple title", "Toast titles should use the informal heading style": "Deleted 1 old download", "Could not download “Letters home”: the server answered with error 404".
10. **[PASS] Empty states.** Placeholder Pages: "All placeholders should include a heading which communicates the empty state and provides guidance": Queue Is Empty, No Downloads, each with one line.
11. **[PASS] Preferences.** Switches: "If a feature has been disabled or is unavailable, it is better to make the switch insensitive": the rows under Delete Old Downloads are unavailable while it is off. Preferences opens with Ctrl+, and is in the shortcuts dialog.
12. **[PASS] Translation.** Every new string goes through gettext; `ui/downloads.rs` was missing from `POTFILES.in` and was added. Sizes come from `g_format_size`, so they follow the locale.

## Notes for the user's review

- With three window buttons the narrow headers shorten their titles ("Que…", "Do…"); GNOME's default close button alone leaves room. Hiding Select while a section is empty would give the title back some room there.
- The drop highlight on the row under a dragged one cannot be seen headless (the dragged row covers it); worth a look on a real desktop, with a touchpad and a touchscreen.
