# HIG review: M3 library views

Result: **PASS**, with fixes made during the review and two items for the user (the two-item sort menu and the Shows order).

Files: `app/` (`mod.rs`, `library.rs`, `window.rs`), `ui/content.rs`, `ui/shows_grid.rs`, `ui/new_view.rs`, `ui/show_page.rs`, `ui/show_hero.rs`, `ui/add_page.rs`, `ui/details_pane.rs`, `ui/widgets/episode_row.rs`, `ui/covers.rs`, `ui/format.rs`, `ui/errors.rs`, `data/style.css`, `data/shortcuts-dialog.ui`.

Pages checked (2026-10-29): list and column views, boxed lists, grid views, buttons (toggle buttons), view switchers, dialogs and toasts, at https://developer.gnome.org/hig/patterns/…; from M0 and M2: menus, placeholders, writing style, header bars, search.

## Findings

1. **[PASS] Long episode lists use list views.** List and column views: "List views are an alternative to boxed lists, which are able to handle very large lists of content, as well as those with dynamic content." New and podcast pages are `GtkListView`s; a podcast page is one virtualized list, hero and seasons included.
2. **[PASS] Rows stay simple, with two controls.** "Keep list rows simple and regular." Boxed lists: rows "should generally just have one, and should have a maximum of two" controls. Rows have the play button and the row menu; the row itself opens the details.
3. **[PASS] Lists have a maximum width.** "Lists and column views should have a minimum and maximum width." Clamped at 900px.
4. **[FIXED] The Shows grid had no maximum width.** Grid views: "Often, grid views should be given a maximum width, in order to prevent uncomfortably long rows." Now clamped at 1200px.
5. **[NOTE, user] Shows order.** Grid views: "Ordering content according to most recently added is often the best arrangement." Shows are sorted by title; recorded in `docs/decisions.md` for the user.
6. **[PASS] Grid tiles have unique thumbnails where possible.** "Wherever possible, each grid item should have a unique thumbnail." Each show uses its cover; shows without one get a neutral placeholder.
7. **[PASS] The RSS Feed row is a boxed list.** Boxed lists suit "relatively small static lists"; the row holds one button.
8. **[PASS] All / Unplayed uses a toggle group.** Linked toggle buttons suit options that "can be expressed with short labels"; the requirements ask for this control.
9. **[NOTE, user] The sort menu has two items.** Menus: "Menus should contain between three and twelve items". The requirements ask for exactly Newest First and Oldest First; recorded for the user. The row menu (five items, two groups) and More Options (three) are within the range.
10. **[PASS] Unsubscribe is confirmed.** Dialogs: "Destructive actions should always be accompanied by either a confirmation dialog or an offer to undo the action". Undo is not possible (the show's data is deleted), and a confirmation is advised "to alert the user to the risk". Cancel comes first and Escape cancels.
11. **[FIXED] The dialog's default button.** "Assign the return key to activate the affirmative button. However, this should not be done if its action is irreversible, destructive … If there is no appropriate button to designate as the default button, do not set one." Cancel had been the default; there is now none.
12. **[PASS] Toasts report events, briefly.** Toasts: "best suited to communicating individual events"; "Each toast should have a short and simple title." Subscribed, unsubscribed, new episodes, failed refreshes, copied feed address, and errors ("For simple non-critical errors, toasts can be a good alternative").
13. **[FIXED] Text ending in a period.** Writing style: "Text generally shouldn't end with a period. This applies to headings, descriptions, and includes text that is written as a complete sentence." Four strings fixed.
14. **[PASS] Neutral Unsubscribe, one suggested button per view.** Buttons: "Each view should only ever include a single button using either the suggested or destructive styles." Unsubscribe and More Options are plain buttons; Add Feed is the Add page's one suggested button.
15. **[PASS] Header capitalization** for headers, menu items and buttons ("Last Week", "Earlier in the Month", "Mark All as Played", "Copy Feed Address"); sentence style for toasts and descriptions.
